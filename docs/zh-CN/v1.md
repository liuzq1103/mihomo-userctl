# V1 命令与配置契约

- 状态：**V1 文档基线**。命令与参数以本文为准，并与冻结的
  [V1 架构契约](../architecture-v1.md)一致。
- 本文描述的是 V1 的**目标命令面**。实现由 `mihomoctl` Python 包提供；
  与实际实现存在差异时，以 `--help` 与 `mihomoctl version` 的输出为准，并按
  [变更记录](../../CHANGELOG.md)更正本文。
- 架构决策见 [architecture-v1.md](../architecture-v1.md)，
  外部事实与边界推导见 [design-reference.md](../design-reference.md)，
  代码审计见 [code-audit.md](../code-audit.md)。

V1 的领域模型是四层：**Proxy Profile + Environment Injection + Runtime Integration
+ Health Check**。核心不含任何具体工具的专属代码；适配器只认识 `kind`，不认识工具名。

## 1. 三个必须先记住的边界

1. **安装器不写任何 Shell 启动文件。** 不修改 `.bashrc` / `.zshrc` / `profile`，
   不注册别名或函数，不注入 hook。初次使用与登录态无关：`mihomoctl exec`、
   `mihomoctl env`、binding 都是显式调用。
2. **环境变量是创建时继承，不是持续策略。** 已运行的进程不会因为配置变化而更新；
   本工具不代你重启任何第三方进程或单元。
3. **本工具不管理第三方应用生命周期。** systemd drop-in、env-file、容器与 CI
   配置只**导出**或只**写入**，永不 `enable` / `start` / `stop` / `restart` 别人的单元。

## 2. 作用域

| | 用户作用域（默认） | 系统作用域 |
| --- | --- | --- |
| 选择方式 | 默认 | 必须显式 `--system` |
| 运行后端 | 默认 `process` | 必须 `systemd` |
| 提权 | 不需要 | 由管理员自行使用 `sudo`，工具**不自行提权** |
| 配置文件 | `$XDG_CONFIG_HOME/mihomoctl/manager.yaml` | `/etc/mihomoctl/manager.yaml` |
| 数据/缓存/运行目录 | XDG data / cache / runtime | `/var/lib` · `/var/cache` · `/run` |
| TUN | **不可用** | 仅管理员显式 `--system tun enable` |

- `--user` 与 `--system` 互斥，缺省为 `--user`。
- UID 0 不自动提升作用域：root 不加 `--system` 可读取用户路径，
  但变更操作会被拒绝。
- 系统作用域的任何变更都需要 UID 0，并显式前置 `--system` 全局参数。
- 用户作用域**不能**创建 TUN、不能改全局网络状态、不能管理系统单元、
  不能影响其他用户的文件或进程。
- 系统配置绝不从 `HOME`、当前目录或不可信环境变量推导。

## 3. 生命周期

```text
mihomoctl init --core PATH [--config FILE] [--allow-non-loopback ADDRESS]
mihomoctl init --help
```

- `init` 显式创建受管配置、凭据、默认 profile 和一个**仅回环、已认证**的命名
  mixed listener。
- 导入已有配置会先校验再复制进受管目录，并保留其路由策略。
- 外部引用的内核二进制保持 **adopted / 只读**，直到执行显式的受管内核安装。

```text
mihomoctl [--user|--system] start
mihomoctl [--user|--system] stop
mihomoctl [--user|--system] restart
mihomoctl [--user|--system] status  [--json]
mihomoctl logs [--lines N] [--follow]
mihomoctl tun status [--json]
```

这几个是**管理 Mihomo 自身运行时**的一级命令，默认 process 后端直接使用。
运行后端与单元由 `service` 显式管理（并列提供，不是替代）：

```text
mihomoctl [--user|--system] service install
mihomoctl [--user|--system] service start
mihomoctl [--user|--system] service stop
mihomoctl [--user|--system] service restart
mihomoctl [--user|--system] service status [--json]
mihomoctl [--user|--system] service uninstall [--dry-run]
```

`service install` 只写受管文件并 reload 自己的 manager，**从不** enable、start
或设置 linger；启停始终是显式的一次动作。

**`status` 固定报告七项事实**：core、controller、每个 listener、生效配置、
proxy layer、Mihomo 路由模式、TUN、错误。缺任何一项都显示为 `unknown` /
`UNVERIFIED`，不会因为数据不完整而显示为正常。

## 4. 受管内核

```text
mihomoctl core install --version VERSION [--sha256 DIGEST]
mihomoctl core update --version VERSION [--sha256 DIGEST] [--dry-run]
mihomoctl core version [--json]
```

- 安装与更新是**显式**操作：固定版本 + 摘要校验，不会被隐式触发。
- 已知版本使用仓库内维护者固定摘要；不匹配即失败。**未知版本必须显式提供
  `--sha256 DIGEST`**，否则拒绝。没有摘要就没有可校验的对象，不提供绕过开关。
- 校验包含 HTTPS 传输及解压大小上限、维护者固定摘要或显式摘要的 SHA256 比对、
  ELF 架构检查及 `mihomo -v` 输出中的目标版本。
- **可说与不可说**：可以说"与维护者固定摘要一致"。**不可**说"已校验官方发布"、
  "已签名验证"或"可复现构建" —— 上游没有发布签名，构建也不可复现。
- `mihomoctl init` 与常规 CLI 操作**永不**隐式下载或替换内核。
- 下载与校验在停止旧内核**之前**完成；激活失败恢复先前的二进制与配置。

## 5. Proxy Profile

Profile 是纯数据模板，**不含凭据**。凭据由运行时自己持有，profile 只描述
"如何引用"。管理文件 `manager.yaml` 的规范形状：

```yaml
version: 1
core:
  binary: /absolute/path/to/mihomo
  config: /absolute/path/to/config.yaml
  backend: process
default_profile: default
profiles:
  default:
    http_listener: proxy
    socks_listener: proxy
    credentials_file: /absolute/private/path/credentials.yaml
    no_proxy: [localhost, 127.0.0.1, '::1']
    health:
      timeout: 10
bindings:
  worker:
    profile: default
    adapter: systemd
    target: worker.service
    connect_host: 127.0.0.1
```

- profile 通过**命名 listener** 解析端口，不存在第二份端口设置。
- 未知字段、重复 YAML 键、不安全 alias、非法作用域路径与跨作用域密钥引用
  会被拒绝，并给出可操作的错误。
- 用户作用域的数据与凭据目录为私有权限；系统作用域的核心可读配置为
  root 属主 `0640` 并带专用服务组，manager 与密钥文件保持 root 私有。

```text
mihomoctl profile list [--json]
mihomoctl profile show NAME [--json]
mihomoctl profile validate NAME [--json]
mihomoctl profile set-default NAME [--json]
```

## 6. 环境注入

```text
mihomoctl env show [--profile NAME | --binding NAME] [--reveal] [--json]
mihomoctl env export [--profile NAME | --binding NAME]
              (--output PATH | --reveal) [--json]
mihomoctl exec [--profile NAME | --binding NAME] -- COMMAND [ARGS...]
```

生成的变量是 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY` 及其小写对应项。
HTTP(S) 使用具备 HTTP 能力的 endpoint，`ALL_PROXY` 使用 `socks5h`。缺少对应协议
支持时**报告**，不猜测。URL 中的凭据会做百分号编码。

- `exec` 在应用所选 profile 之前只清除这**八个**继承来的代理变量，其余环境保持不变。
- `exec` 在 `execve` 前要求本地健康检查通过（fail-closed），随后**透明透传**目标命令的
  退出码与信号结果。
- `exec` 与环境注入**都不修改父 Shell**，也不修改 systemd 的 manager 环境。
- `env show` 默认显示脱敏投影，`--reveal` 显式显示真实值；
  `env export` 产出可接入的声明文件。
- `--output PATH` 把真实值写到显式的私有输出文件；写 stdout 必须显式 `--reveal`。
  凭据**不得**出现在 argv、unit 文本、异常信息或日志中。

## 7. 接入（声明式）

内置 adapter：`exec`、`systemd`、`docker`、`kubernetes`、`supervisor`、`pm2`、`ci`。

```text
mihomoctl integration list [--json]
mihomoctl integration show NAME [--json]
mihomoctl integration check NAME [--json]
mihomoctl integration export NAME [--output-dir DIR | --reveal] [--json]
mihomoctl integration install NAME [--json]
mihomoctl integration remove NAME [--json]
```

| 目标形态 | V1 做什么 | V1 **不**做什么 |
| --- | --- | --- |
| `exec` | **原生**：设置环境后 `execvp`，透传 argv 与退出码 | 不修改目标已有环境；不观测该进程后续行为 |
| `systemd` 用户 | **原生**：写私有 `proxy.env` 与带标记的受管 drop-in，并 `daemon-reload` | 不执行 `start/stop/restart/enable`；**不向消费者环境导出 Controller secret** |
| `systemd` 系统 | 生成 unit 片段；**仅 TUN 启用时**加 `CapabilityBoundingSet` / `AmbientCapabilities` | 不 `sudo`，不自行提权 |
| `docker` / `compose` | **仅导出**：env-file 片段与 `env_file` 片段 | 不重启容器、不调用 Docker API、不改 compose 文件 |
| `kubernetes` | **仅导出**：ConfigMap/Secret 片段与 `envFrom` 片段 | 不 `apply`、不等待 rollout |
| `pm2` | **仅导出**：`ecosystem` 的 env 片段 | 不重启进程 |
| `supervisor` | **仅导出**：原生 `environment=` 程序片段 | 不代你执行 `reread` / `update` |
| `ci` | **仅导出**：流水线环境步骤片段 | 不代替流水线执行 |

### 容器必须显式指定可达地址

**容器内的 `127.0.0.1` 是容器自己的回环，不是宿主机回环。**
`docker` / `kubernetes` / `compose` 导出时会使用显式的 `connect_host`；
通配地址**永远不会被当作客户端地址输出**。跨网络命名空间的 binding 必须给出
真正可达的地址。

### systemd 硬约束

- `EnvironmentFile=` 不加 `-` 前缀：缺文件即启动失败，保留 fail-closed 门禁。
- 接入写出的 `proxy.env` 包含**真实代理 URL 与凭据**，因此它是
  **私有敏感文件**：权限 `0600`、属主与运行账号一致、带受管标记。
  它不能与 `0600` 的核心配置或凭据文件合并。
- mihomo 的 `secret` **不得**出现在 `Environment=` / `EnvironmentFile=` /
  `CLASH_OVERRIDE_SECRET` / `-secret`。理由不是"某个 UID 一定能读到某个 unit 的
  环境"，而是更基本的一条：**环境变量不是秘密隔离机制**。它会随进程树传播，
  会出现在诊断输出、崩溃报告和进程检查工具里，其保护强度取决于文件权限与
  部署方式，而不是变量名。正确做法是把 `external-controller` 与 `secret`
  写进 `0600` 的生成配置文件，由 mihomo 自行读取。
- `EnvironmentFile=` 是**接入格式，不是秘密隔离机制**：变量会随进程树传播，
  并可能出现在诊断输出中。因此对该文件的保护依赖文件权限与部署方式，
  而不是变量名称本身。受限导出照常提供，但输出端必须保持私有。
- `ExecStart=` 必须是直接 argv；禁用 `|` / `;` / `&&` / `||` 等一切 shell 包装前缀。
- 安装 unit 只写受管文件并 reload 自己的 manager：**从不** enable、start 或设置 linger。

## 8. 健康检查

```text
mihomoctl health check [--profile NAME | --binding NAME] [--egress-url URL] [--json]
```

只针对运行时，不针对任何工作负载。检查项使用 `PASS` / `FAIL` / `UNVERIFIED` /
`SKIPPED`，每项同时标注证据等级 `confirmed` / `inferred` / `unavailable`。

| 检查 | 手段 | 证据等级 |
| --- | --- | --- |
| 服务态 | 单元状态查询 | `confirmed`（仅证单元态） |
| 监听存在 | 回环监听探测 | `confirmed`（仅证有监听） |
| 监听归属 | `/proc` 同 UID 归属核对 | `inferred` |
| 代理可用 | 带认证的 HTTP 探针 | `confirmed`（仅证该请求经该代理） |
| 可选外部目标探测 | 显式 `--egress-url URL` 的请求结果 | 仅该次探测，不证明应用流量 |

每次 `health` 输出都会固定附带以下边界声明：

- `readiness-is-not-model-e2e`
- `listener-presence-does-not-prove-ownership`
- `authenticated-probe-does-not-prove-a-remote-node`
- `node-selection-does-not-prove-one-request`
- `unobserved-socket-does-not-mean-a-direct-connection`

外部出网检查是**可选**的，且**永不**作为安装或本地启动的成功门禁。

## 9. TUN

TUN 是独立模块，**默认关闭**。

```text
mihomoctl tun status [--json]
mihomoctl --system tun enable        # 仅管理员
mihomoctl --system tun disable        # 仅管理员
```

- 只有管理员显式调用 `--system tun enable` 才会授权启用；用户作用域不存在这个选项。
- V1 仅在管理员显式选择系统作用域时启用 TUN；这是产品权限策略。内核能力和设备属主规则不能推出所有 TUN 使用都必须是 UID 0。
- 启用在一个可回滚事务内完成：更新核心配置、写授权回执、写服务能力 drop-in。
- 仅在启用时授予 `CAP_NET_ADMIN`；不做全局 `setcap`，不使用特权 helper。
- 关闭与回滚恢复先前受管文件，只处理本工具自有的设备与路由；
  **绝不**清空宿主机路由表或防火墙规则。
- 任何应用或策略 adapter 都不能启用 TUN。
- 改变网络的验收在一次性网络命名空间中执行。

## 10. 输出契约

JSON 是**单一信封**：

```json
{"schema":"mihomoctl/v1","command":"status","scope":"user","overall":"PASS",
 "data":{},"checks":[],"errors":[]}
```

- 检查项使用 `PASS`、`FAIL`、`UNVERIFIED`、`SKIPPED`，证据使用 `confirmed`、
  `inferred`、`unavailable`。
- 退出码：`0` 成功，`1` 已观测到失败或健康阻断，`2` 用法/权限/无法验证。
- `exec` 启动之后，子进程的退出结果**不再重映射**。
- 日志必须脱敏。
- `status` / `health` 的所有输出都是脱敏的。

## 11. 迁移

```text
mihomoctl migrate [--dry-run] [--apply] [--json]
```

`--dry-run` 只预览，`--apply` 才执行；两者都不是独立子命令。

- 迁移是显式的 preview / apply 操作：导入旧配置与凭据，**只移除能确证属于本项目的
  loader**，保留文件其余字节，并备份所有被修改的文件。
- 被自定义或形态含糊的 loader 一律**拒绝**，不猜测。
- 已存在的第三方单元只**报告**，绝不停止或删除。
- 安装器不默认修改任何启动文件。

## 12. 旧命令退役

V1 不管理任何第三方 daemon 生命周期。旧的应用专属用法已经退役，
请迁移到下表中的显式通用入口：

| 旧命令 | V1 行为 | 改用 |
| --- | --- | --- |
| `mihomoctl paseo start\|stop\|restart\|run\|install-unit` | 已退役，拒绝执行并提供迁移指引 | 定义 binding 后使用 `mihomoctl integration install NAME`；消费者重启由你自行安排 |
| `mihomoctl codex [-- ARGS...]` | 已退役，不提供兼容别名 | `mihomoctl exec -- COMMAND ARGS...` |
| `mihomoctl codex preflight` | 已退役，不提供兼容别名 | `mihomoctl health check` |
| `mihomoctl diagnose codex` | 已退役，不提供公共 `diagnose` 命令 | `mihomoctl health check` / `mihomoctl doctor` |
| `.bashrc` 中的 `CODEX_REMOTE_PAYLOAD` hook | 已删除 | `mihomoctl exec`（预检不过绝不执行） |

旧教程见[归档说明](paseo.md)：命令面已退役，但迁移思路仍可读。

## 13. 退出码与证据

| 码 | 含义 |
| --- | --- |
| `0` | 目标达成 |
| `1` | 已观测到失败或健康阻断 |
| `2` | 用法错误、权限不足、依赖缺失，或无法可靠验证 |

`UNVERIFIED` 是合法终态，不是失败；但它**不得**被降级呈现为 `PASS`。
详细验收要求见[验收与证据](acceptance.md)。
