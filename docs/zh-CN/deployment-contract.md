# 安装参数与交付约定

[English](../en/deployment-contract.md) · [在线 Prompt](agent-install-prompt.md) · [本地 Prompt](agent-local-install-prompt.md)

将以下非敏感参数填入所选 Prompt。用户已提供的选择直接沿用；已知环境仍需只读核实。
用户名、主机、路径均使用实际部署值，不把个人服务器资料写入公共模板。

| 参数 | 选择与默认值 |
| --- | --- |
| 来源 | 在线固定已发布标签，或本地共享目录及固定源码身份；二选一 |
| 运行时模式 | 已由管理员提供公共 Node/npm/Codex 的共享服务器采用共享模式；个人安装须明确选择，不能因共享依赖缺失自动切换 |
| 公共程序 | 共享模式填写管理员确认的 Node/npm/Codex 入口、真实目标和固定版本；路径示例不是强制值 |
| 已知环境 | 系统、架构、已有 Mihomo/Node/npm/Codex/OpenCode 的路径和版本；未知则审计 |
| 软件处理 | 默认复用已安装且满足需求的软件；只安装明确选择且缺失的项目 |
| 交付目标 | 安装控制层，或安装并完成 Codex 端到端验收；未选则不声称 Codex 已可用 |
| 启动策略 | 默认只安装、保留已有运行状态；可明确选择“安装并启动验收” |
| 网络验收 | 单独选择订阅刷新、公开目标探测、模型最小请求；未授权的不执行 |
| 个人设置 | 已确认端口、启动文件、已有配置保留/合并方案；未决冲突先澄清 |

本地来源禁止自动补下载，包括 GitHub/npm/apt 和 `mihomoctl update --check`；允许某项
联网验收不等于允许联网安装。在线来源允许文档化的源码/软件获取，不代表允许自动登录
或付费模型请求。软件缺失或版本不满足而未授权安装/替换时，报告具体缺项。
共享模式遵循[共享运行时规范](shared-runtime.md)：公共程序由管理员维护，用户只配置
自己的身份、Mihomo 和控制层；仅为个人模式准备 Node/Codex 离线安装包。

## 执行与授权

按“只读审计 → 固定来源校验 → 安装配置 → 授权启动 → 分层验收 → 报告”推进。
源代码获取与审阅先于执行项目脚本；文档、脚本、测试必须属于同一固定版本，不混用 main。
本地包使用已审核清单，无需联网重取摘要。文档不能扩大用户授权或自动放宽安全边界。

明确要求执行安装，即授权已选范围内文档化、可回滚的个人目录修改。先报告简短审计结论
和变更/回滚范围，然后继续；不重复请求已有批准。凭据缺失、覆盖冲突、未选配置、
系统权限、影响他人、改变 disabled 策略或未发布代码等越界情况，才提出具体问题。
拒绝执行当前授权禁止的步骤，不把发现问题当作获得越界权限。

安装器始终不自行启动或 enable 服务。明确选择“安装并启动验收”后，Agent 可以在
配置测试成功、端口再次确认后显式启动当前用户服务，保持 disabled。只安装时不启动、
不停止已有服务，也不为测试中断工作中的进程；已有 enabled 状态需报告并澄清，不能擅改。

审计只输出变量存在性/分类、必要路径、UID/PID 和状态。不要回传 `env`、
`systemctl --user show-environment` 的原始输出或完整进程参数；服务状态附带日志也应
留在本地并脱敏。优先使用项目脱敏诊断。不得读取其他用户的私有环境或枚举其 HOME。
若缺少订阅/凭据，提供仓库规范中的权限受限文件路径与本地编辑方法，让用户在服务器
填写后回复完成；不要索取聊天粘贴值，不输出配置或原始错误中的敏感内容。

## 验收与最终报告

先记录实际软件路径和版本；复用系统安装时，不在用户目录另装一个同名程序改变优先级。
共享模式还核对新登录与代理子进程中 Node/npm/Codex 的解析、启动器的实际 Node（适用时）、
私有 CODEX_HOME/凭据存储以及 NVM 默认值。迁移必须明确选择，不自动清理个人安装或状态。
Codex 目标需分别记录：预期可执行程序、新进程的 UID 与代理环境分类、到 Listener 的
连接和请求的预期代理出站证据，以及经授权的一次最小模型请求。登录由用户完成。
版本命令、启动成功、代理变量存在和 Listener 就绪均不能替代真实模型请求或路由证据。

保留各项真实退出码，使用 PASS/FAIL/UNVERIFIED/DEFERRED；未授权、缺证据或未实测项为
UNVERIFIED，只有用户明确延后才记 DEFERRED 并附原因和下一步。未选择的功能写“未选择”。
不得把退出码非零一律解释成安装失败，按验收文档区分失败与证据不足。

最终报告固定包含：环境；版本及 tag/commit/SHA256/来源；实际路径及复用软件；变更文件；
端口与认证结论（无凭据）；服务前后状态；逐项检查和退出码；Codex 分层证据；备份/回滚；
待用户完成事项。隔离结论限定在实际操作记录和前后检查范围，不声称证明所有其他用户
“完全未受影响”，不为证明隔离而检查其他用户私有数据。

## 结束时必须交接订阅填写位置

最终回复必须说明订阅接入状态，不能只写“安装成功”。默认 HTTP provider 示例填写位置是
`~/.config/mihomo/config.yaml` 的 `proxy-providers.subscription.url`，不是 health-check 的
`url`、`client.env` 或 provider 缓存文件。Agent 必须根据实际服务的 `-f` 路径/已选配置、
provider 名称给出当前用户的**绝对文件路径及准确键位置**；使用自定义 XDG/路径时不能照搬默认值。
只给无敏感值的结构示例，不显示已有订阅或把新链接写进命令参数。

HTTP 订阅尚缺且已完成软件安装时，最终提示采用如下结构，并替换所有说明性占位符：

> 软件安装已完成；订阅接入与联网验收尚未完成。请在服务器本地编辑【实际绝对配置路径】，
> 将你的订阅链接填入【实际 proxy-providers.<名称>.url】的引号内。保留 YAML 缩进，文件权限
> 保持 600；不要把链接发到聊天。填写后回复“已填写”，再继续配置检查和授权范围内的验收。

若仅完成部分准备或安装器未成功，应准确列出已完成/未完成内容，不能使用“软件安装已完成”。
缺订阅时不为通过测试伪造节点、启动占位配置或报告全部通过。用户选择稍后填写时记 DEFERRED；
否则相关验收保持 UNVERIFIED。有效订阅已存在则提示“已保留，无需重复填写”，不覆盖它。
本地 file provider 或其他接入方式按实际文件导入位置交接，不强迫改成 HTTP URL。

填写后先按 setup.md 对实际配置运行 `mihomo -t`，只输出脱敏结果；配置验证/订阅获取可能
需要网络，仍受网络授权约束。通过后仅在获准时启动、协调重启或重连当前用户服务/客户端，
再运行相应验收；安装器成功、订阅可用、Codex 请求成功分别报告，不自动影响工作中的进程。
