# 保留订阅策略与自动故障转移

订阅导入默认按内容判断：只有 `proxies` 的清单合并节点，完整策略保留提供商的规则、组名、组类型、候选顺序和探测参数。显式 `--policy provider` 或 `--policy nodes` 优先。提供商模式整体替换路由策略，缺失策略字段清空，预览列出移除范围和覆盖的现有探测设置。本机监听、认证、Controller、DNS、TUN 保留。

## 检查已有自动路径

```bash
mihomoctl groups --json
mihomoctl tui
```

`selection_chain` 是核心当前选择链路，`automatic_candidates` 是沿现有手动组可选择的自动路径，`affected_groups` 是当前经由此入口的其他组。`warnings` 区分手动路径绕过自动组、无探测记录、全部已观测探测失败及核心报告的固定选择。循环、缺失引用、未知选择均单独报告。观测没有业务成功承诺，历史探测也不能证明当前应用可用。

Textual 节点页输入 `: chain` 查看当前组的路径与风险；编号菜单进入“选择节点”后显示相同诊断。按路径逐个选择、确认和读回，不自动批量改变入口。共享入口的变化会影响其他业务组，确认框会列出这些组。

例如，含业务入口、手动选择和自动选择组的订阅可能已有以下链路（以下使用合成名称，替换为自己订阅的实际名称）：

```text
业务组 → 手动选择 → 自动选择（url-test）→ 节点
```

先检查实时选择。若业务组固定到了单个节点，显式选回共享入口；若共享入口固定到单个节点，再选回已有自动组：

```bash
# 仅在这些名称及成员关系确实存在，并检查共享影响后使用
mihomoctl select '业务组' '手动选择'
mihomoctl select '手动选择' '自动选择'
mihomoctl groups --json
```

其他订阅使用自己的组名与路径。本工具不按业务名称重写规则，也不把所有 select 转成自动组。若自动组自身报告 `fixed`，应使用对应核心支持的恢复自动选择方式；切换外层入口不等于清除了它。

## 可选探测调整

```bash
# 只读展示，不修改配置
mihomoctl health-check group '自动选择'
# 预览建议参数，确认后再保存
mihomoctl health-check group '自动选择' --preset resilient
mihomoctl health-check group '自动选择' --preset resilient --apply
mihomoctl restart
```

`resilient` 设置 HTTPS gstatic 地址、期望状态码 204、间隔 120 秒、超时 5000ms、`lazy: false`，url-test 容差 50ms。导入不会自动套用预设；显式参数覆盖预设。可用参数：`--url`、`--expected-status`、`--interval`（秒）、`--timeout`（毫秒）、`--lazy true|false`、`--tolerance`（毫秒，仅 url-test）。期望状态可写 `204`、`200/204` 或 `200-299`。新增 URL 必须为公开 HTTPS，不能包含凭据、查询或 fragment。

```bash
# 共享 provider 需要单独审阅；修改会影响列出的引用组
mihomoctl health-check provider subscription --preset resilient
```

组级探测与 provider 探测不是可随意叠加的独立计时器；通过 `use` 引入节点时，provider 的探测调度可能控制实际周期。预览展示相关 provider 设置并提示共享影响；工具只修改明确指定的对象。provider 预设同时启用健康检查；单独修改其他字段不会隐式启用原本关闭的检查。

Textual 输入 `: health-check group "组名" --preset resilient` 预览，再按 `y` 保存；编号菜单选择“探测配置”，使用相同参数。所有保存先执行核心校验，并复用私有备份、并发修改保护和原子写入。保存后需单独重启。再次导入订阅以提供商策略为准，可覆盖本地探测调整；预览显示覆盖摘要。

检查地址可自定义为无需认证且返回稳定状态的目标。gstatic 成功仅证明该检查目标可达，不能证明 OpenAI 等服务接受此出口；451、405 等响应也不能独自证明真实模型请求成功。工具不自动把业务接口加入持续探测。

## 按故障时间查询日志

```bash
mihomoctl logs --since '2026-10-10 21:09:00' --until '2026-10-10 21:14:00' --lines 1000
```

时间由服务器 journal 解析。Textual 可用 `: journal --since "2026-10-10 21:09:00" --until "2026-10-10 21:14:00"`，编号菜单可用“历史日志”；控制台保留脱敏和行数上限，区分查询失败与窗口内无记录。CLI logs 沿用原始 journal 输出，可能含私有目标信息，分享前审阅。

journal 的保留范围、持久存储和轮转由服务器决定。窗口内无记录不证明当时没有故障，也不保证重启后能取回历史。本次没有新增独立日志文件或守护进程。

## 验收边界

真实核心测试使用两个本地可控 CONNECT 代理和本地目标：关闭当前出口后，新连接改走备用出口；全部出口关闭时，诊断显示已观测探测失败。测试不使用真实订阅或公网节点。恢复时间应包含探测周期、超时、候选规模和核心缓存/调度余量；不能据 120 秒周期推出 99.5% 可用性，也不保证故障期间零请求失败。已断开的连接需业务重试，配置重启会中断连接。

事故中配置缺少自动路径可以直接检查；某个节点是否在历史故障窗口宕机，需要当时日志等证据，不能用事后可达性补证。
