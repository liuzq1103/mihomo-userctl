# V1 command and configuration contract

- Status: **V1 documentation baseline**. Commands and flags follow this document
  and the frozen [V1 architecture contract](../architecture-v1.md).
- This describes the V1 **target command surface**. The implementation lives in the
  `mihomoctl` Python package. When it differs from this document, `--help` and
  `mihomoctl version` are authoritative and this file is corrected through the
  [changelog](../../CHANGELOG.md).
- Decisions: [architecture-v1.md](../architecture-v1.md); verified external facts
  and the boundaries they imply: [design-reference.md](../design-reference.md);
  code audit: [code-audit.md](../code-audit.md).

V1 is abstracted as four layers: **Proxy Profile + Environment Injection +
Runtime Integration + Health Check**. The core carries no application-specific
code; an adapter knows a `kind`, never a tool name.

## 1. Three boundaries to know first

1. **The installer writes no shell startup file.** No `.bashrc` / `.zshrc` /
   `profile` edit, no aliases, no functions, no injected hook. First use does not
   depend on a login shell: `mihomoctl exec`, `mihomoctl env` and bindings are
   always explicit invocations.
2. **Environment variables are inherited at process creation; they are not a
   continuous policy.** A running process does not change because configuration
   changed, and this tool never restarts a third-party process or unit for you.
3. **This tool does not manage third-party application lifecycles.** systemd
   drop-ins, env files, container and CI configuration are only **exported** or
   **written**; the tool never `enable`s, `start`s, `stop`s or `restart`s someone
   else's unit.

## 2. Scope

| | User scope (default) | System scope |
| --- | --- | --- |
| Selected by | default | explicit `--system` only |
| Backend | `process` by default | `systemd` required |
| Privilege | none needed | the administrator uses `sudo`; the tool **never self-escalates** |
| Management file | `$XDG_CONFIG_HOME/mihomoctl/manager.yaml` | `/etc/mihomoctl/manager.yaml` |
| Data / cache / runtime | XDG data / cache / runtime | `/var/lib` · `/var/cache` · `/run` |
| TUN | **unavailable** | administrator-only `--system tun enable` |

- `--user` and `--system` are mutually exclusive; the default is `--user`.
- UID 0 does not get an automatic promotion: root without `--system` may inspect
  user paths; mutations are refused.
- System-scoped changes require UID 0 and an explicit leading `--system` flag.
- User scope **cannot** create TUN, touch global network state, manage system
  units, or affect another user's files or processes.
- A system configuration is never discovered from `HOME`, the working directory
  or an untrusted environment variable.

## 3. Lifecycle

```text
mihomoctl init --core PATH [--config FILE] [--allow-non-loopback ADDRESS]
mihomoctl init --help
```

- `init` explicitly creates the managed configuration, credentials, a default
  profile and one **loopback-only, authenticated** named mixed listener.
- Importing an existing configuration validates it first, copies it into managed
  storage, and preserves its routing policy.
- An externally referenced binary stays **adopted / read-only** until an explicit
  managed core install.

```text
mihomoctl [--user|--system] start
mihomoctl [--user|--system] stop
mihomoctl [--user|--system] restart
mihomoctl [--user|--system] status  [--json]
mihomoctl logs [--lines N] [--follow]
mihomoctl tun status [--json]
```

These are the **first-tier commands that manage the Mihomo runtime itself**, and
they are what the default process backend uses. The backend and unit are managed
through `service` as well, offered in parallel rather than as a replacement:

```text
mihomoctl [--user|--system] service install
mihomoctl [--user|--system] service start
mihomoctl [--user|--system] service stop
mihomoctl [--user|--system] service restart
mihomoctl [--user|--system] service status [--json]
mihomoctl [--user|--system] service uninstall [--dry-run]
```

`service install` only writes owned files and reloads its own manager; it **never**
enables, starts, or sets linger. Starting and stopping stay explicit actions.

**`status` always reports seven facts**: core, controller, every listener, the
active config, the proxy layer, the Mihomo routing mode, TUN, and errors. Any
missing fact renders as `unknown` / `UNVERIFIED`; partial data never renders as
healthy.

## 4. Managed core

```text
mihomoctl core install --version VERSION [--sha256 DIGEST]
mihomoctl core update --version VERSION [--sha256 DIGEST] [--dry-run]
mihomoctl version [--json]
```

- Install and update are **explicit**: a fixed version plus a digest gate. They
  are never triggered implicitly.
- Known versions use the repository's maintainer-curated pin; a mismatch fails.
  **An unknown version requires an explicit `--sha256 DIGEST`**, otherwise it is
  refused. Without a digest there is nothing to verify, and no bypass switch exists.
- Verification uses bounded HTTPS transfer and decompression, SHA256 against
  the maintainer pin or explicit supplied digest, ELF architecture checks, and
  the requested version in `mihomo -v` output.
- **What may and may not be claimed**: you may say "matches the maintainer-curated
  pin". You **may not** say "verified against the official release", "signature
  verified" or "reproducible build" — upstream publishes no signature and its
  build is not reproducible.
- `mihomoctl init` and ordinary CLI operations **never** implicitly download or
  replace the core.
- Download and verification finish **before** the old core is stopped; a failed
  activation restores the previous binary and configuration.

## 5. Proxy Profile

A profile is pure data and holds **no credentials**. The runtime owns the
credentials; the profile only says how to reference them. The canonical shape of
`manager.yaml` is:

```yaml
version: 1
core:
  binary: /absolute/path/to/mihomo
  config: /absolute/path/to/config.yaml
  backend: process
default_profile: default
profiles:
  default:
    http_listener: proxy
    socks_listener: proxy
    credentials_file: /absolute/private/path/credentials.yaml
    no_proxy: [localhost, 127.0.0.1, '::1']
    health:
      timeout: 10
bindings:
  worker:
    profile: default
    adapter: systemd
    target: worker.service
    connect_host: 127.0.0.1
```

- A profile resolves its ports from **named listeners**, never from a second port
  setting.
- Unknown fields, duplicate YAML keys, unsafe aliases, invalid scope paths and
  cross-scope secret references are rejected with actionable errors.
- User-scope data and credential locations stay private. System-scope core-readable
  configuration is root-owned `0640` with the dedicated service group; manager and
  secret files stay root-private.

```text
mihomoctl profile list [--json]
mihomoctl profile show NAME [--json]
mihomoctl profile validate NAME [--json]
mihomoctl profile set-default NAME [--json]
```

## 6. Environment injection

```text
mihomoctl env show [--profile NAME | --binding NAME] [--reveal] [--json]
mihomoctl env export [--profile NAME | --binding NAME]
              (--output PATH | --reveal) [--json]
mihomoctl exec [--profile NAME | --binding NAME] -- COMMAND [ARGS...]
```

Generated variables are `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY` and
their lowercase counterparts. HTTP(S) uses an HTTP-capable endpoint; `ALL_PROXY`
uses `socks5h`. Missing protocol support is **reported**, never guessed.
Credentials inside URLs are percent-encoded.

- `exec` clears exactly those **eight** inherited proxy keys before applying the
  selected profile; unrelated environment is retained.
- `exec` requires confirmed local health before `execve` (fail-closed), then
  **transparently passes through** the target's exit code and signal result.
- Neither `exec` nor environment injection changes the parent shell or systemd's
  manager environment.
- `env show` defaults to redacted projections; `--reveal` explicitly discloses
  real values. `env export` produces the consumable declaration.
- `--output PATH` writes real values to an explicit private output file; writing
  them to stdout requires an explicit `--reveal`. Credentials **must not** appear
  in argv, unit text, exception messages or logs.

## 7. Runtime integration (declarative)

Built-in adapters: `exec`, `systemd`, `docker`, `kubernetes`, `supervisor`, `pm2`, `ci`.

```text
mihomoctl integration list [--json]
mihomoctl integration show NAME [--json]
mihomoctl integration check NAME [--json]
mihomoctl integration export NAME [--output-dir DIR | --reveal] [--json]
mihomoctl integration install NAME [--json]
mihomoctl integration remove NAME [--json]
```

| Target | V1 does | V1 does **not** do |
| --- | --- | --- |
| `exec` | **native**: set the environment, `execvp`, pass through argv and exit code | does not modify the target's existing environment; does not observe its later behaviour |
| `systemd` user | **native**: write a private `proxy.env` and a marked managed drop-in, then `daemon-reload` | never runs `start/stop/restart/enable`; **keeps the controller secret out of consumer proxy environments** |
| `systemd` system | generate unit fragments; add `CapabilityBoundingSet` / `AmbientCapabilities` **only when TUN is enabled** | no `sudo`, no self-escalation |
| `docker` / `compose` | **export only**: env-file fragment and `env_file` fragment | no container restart, no Docker API, no compose file edit |
| `kubernetes` | **export only**: ConfigMap/Secret fragment and `envFrom` fragment | no `apply`, no rollout wait |
| `pm2` | **export only**: the `ecosystem` env fragment | no process restart |
| `supervisor` | **export only**: a native `environment=` program fragment | does not run `reread` / `update` for you |
| `ci` | **export only**: a pipeline environment step fragment | does not run the pipeline |

### Containers need an explicitly reachable address

**`127.0.0.1` inside a container is the container's own loopback, not the host's.**
`docker` / `kubernetes` / `compose` exports use an explicit `connect_host`, and a
wildcard address is **never** emitted as a client address. A binding crossing a
network namespace must name a genuinely reachable address.

### Hard systemd constraints

- `EnvironmentFile=` is never given a `-` prefix: a missing file fails the unit,
  which keeps the fail-closed gate.
- The `proxy.env` an integration writes contains **real proxy URLs and credentials**,
  so it is a **private, sensitive file**: mode `0600`, owned by the account that runs
  the unit, and marked as tool-owned. It is never merged with the `0600` core config
  or the credential file.
- mihomo's `secret` **must not** appear in `Environment=` / `EnvironmentFile=` /
  `CLASH_OVERRIDE_SECRET` / `-secret`. The reason is not "some UID can always read
  some unit's environment"; it is the more basic rule that **an environment
  variable is not a secret isolation mechanism**. Values travel down the process
  tree and surface in diagnostics, crash reports and process inspection, and
  their protection comes from file permissions and deployment, not from the
  variable's name. The correct place is the `0600` generated configuration file
  that mihomo reads itself.
- `EnvironmentFile=` is an **integration format, not a secret isolation mechanism**:
  values propagate down the process tree and can surface in diagnostics. The
  protection therefore comes from the file's permissions and deployment, not from
  the variable's name. The restricted export is still provided, and its output must
  stay private.
- `ExecStart=` must be a direct argv; shell wrapper prefixes (`|`, `;`, `&&`,
  `||`) are forbidden.
- Installing a unit only writes owned files and reloads its own manager: it
  **never** enables, starts, or sets linger.

## 8. Health check

```text
mihomoctl health check [--profile NAME | --binding NAME] [--egress-url URL] [--json]
```

Health applies to the runtime only, never to a workload. Checks use `PASS` /
`FAIL` / `UNVERIFIED` / `SKIPPED`, and each carries an evidence level of
`confirmed` / `inferred` / `unavailable`.

| Check | Means | Evidence |
| --- | --- | --- |
| Service state | unit state query | `confirmed` (unit state only) |
| Listener present | loopback listener probe | `confirmed` (a listener is there only) |
| Listener ownership | same-UID `/proc` check | `inferred` |
| Proxy usable | authenticated HTTP probe | `confirmed` (that request went through that proxy only) |
| Optional external target | explicit `--egress-url URL` request | this probe only; not application traffic |

Every `health` output carries these boundary statements verbatim:

- `readiness-is-not-model-e2e`
- `listener-presence-does-not-prove-ownership`
- `authenticated-probe-does-not-prove-a-remote-node`
- `node-selection-does-not-prove-one-request`
- `unobserved-socket-does-not-mean-a-direct-connection`

External egress checks are **opt-in** and are **never** a success gate for
installation or for a local start.

## 9. TUN

TUN is an independent module and is **disabled by default**.

```text
mihomoctl tun status [--json]
mihomoctl --system tun enable        # administrator only
mihomoctl --system tun disable        # administrator only
```

- Only an administrator explicitly invoking `--system tun enable` authorizes it;
  user scope has no such option.
- V1 enables TUN only in explicit administrator-managed system scope. Kernel
  capability and device ownership rules do not imply that all TUN use requires UID 0.
- Enabling happens in one rollbackable transaction: update the core configuration,
  write an authorization receipt, write the service capability drop-in.
- `CAP_NET_ADMIN` is granted only while enabled; there is no global `setcap` and no
  privileged helper.
- Disabling and rollback restore the prior managed files and touch only the
  tool-owned device and routes; host routes and firewall rules are **never** flushed.
- No application or policy adapter can enable TUN.
- Network-changing acceptance runs in a disposable network namespace.

## 10. Output contract

JSON is a **single envelope**:

```json
{"schema":"mihomoctl/v1","command":"status","scope":"user","overall":"PASS",
 "data":{},"checks":[],"errors":[]}
```

- Checks use `PASS`, `FAIL`, `UNVERIFIED`, `SKIPPED`; evidence uses `confirmed`,
  `inferred`, `unavailable`.
- Exit codes: `0` success, `1` observed failure or health block, `2`
  usage/permission/unverified.
- After `exec` starts, the child's exit result is **not remapped**.
- Logs are redacted.
- All `status` / `health` output is redacted.

## 11. Migration

```text
mihomoctl migrate [--dry-run] [--apply] [--json]
```

`--dry-run` only previews; `--apply` performs the work. Neither is a subcommand.

- Migration is an explicit preview/apply operation: it imports the old config and
  credentials, **removes only a positively identified project loader**, preserves
  the remaining bytes, and backs up every file it modifies.
- A customized or ambiguously shaped loader is **refused**, never guessed.
- Existing third-party units are only **reported**, never stopped or removed.
- The installer never default-edits any startup file.

## 12. Retired commands

V1 manages no third-party daemon lifecycle. Old application-specific usage is
retired; migrate to the explicit generic entries below:

| Retired | V1 behaviour | Use instead |
| --- | --- | --- |
| `mihomoctl paseo start\|stop\|restart\|run\|install-unit` | retired; refused with migration guidance | define a binding, then `mihomoctl integration install NAME`; restart the consumer yourself when appropriate |
| `mihomoctl codex [-- ARGS...]` | retired; no compatibility alias | `mihomoctl exec -- COMMAND ARGS...` |
| `mihomoctl codex preflight` | retired; no compatibility alias | `mihomoctl health check` |
| `mihomoctl diagnose codex` | retired; no public `diagnose` command | `mihomoctl health check` / `mihomoctl doctor` |
| `CODEX_REMOTE_PAYLOAD` hook in `.bashrc` | removed | `mihomoctl exec` (never executes when the gate fails) |

See the [archive note](paseo.md) for the old tutorial: the command surface is
retired but the migration reasoning is still readable.

## 13. Exit codes and evidence

| Code | Meaning |
| --- | --- |
| `0` | objective achieved |
| `1` | observed failure or health block |
| `2` | usage error, missing permission or dependency, or unverifiable |

`UNVERIFIED` is a legitimate final state, not a failure; but it **must not** be
downgraded into `PASS`. Full acceptance requirements: [acceptance and evidence](acceptance.md).
