# Agent installation instructions

For local packages, copy the [complete local installation prompt](agent-local-install-prompt.md), default source `/mnt/nas/public/software`. Complete new setup includes controller, trusted core and initialization, without automatic start; install only the controller when explicitly requested.

Read [INSTALL.md](../../INSTALL.md), [setup](setup.md), [security](security.md) and [verification](first-run.md). Begin with a read-only audit of Linux/Python, existing core/configuration, user scope, XDG paths and available network access. Never print private files or put credentials in argv.

Decide core preparation and network conditions before installation. Preserve an existing manager without reinitialization or proactive core install (which may restart its runtime). For new setup prefer a trusted existing core; otherwise, with network access allowed, on x86_64 explicitly install fixed v1.19.32, init once and validate configuration, without asking for a version. Built-in digests cover only amd64-compatible; other architectures need a corresponding checked digest or trusted local core beforehand. Report missing strict-offline materials before installation; local source does not imply strict offline use.

Install a verified release/dependencies, then complete the chosen core/initialization branch. Reuse existing user data. Preview subscriptions and show only redacted summaries, ID and candidate SHA256; apply only within the user's authorized scope, then explicitly restart Mihomo if requested. Add rules using the documented private-file contract and readonly check. Do not revive retired lifecycle commands or shell hooks.

Honor prior user authorization. Ask only for missing input or destructive actions outside scope; do useful reversible preparation first. No implicit sudo, startup edits, third-party service actions or TUN. Export integrations privately. Record PASS/FAIL/UNVERIFIED with actual evidence, a redacted change summary and a rollback path. Report controller, core and initialization separately; runtime/remote routing remain UNVERIFIED when stopped by default. A successful local proxy test does not prove a real application's remote route. For third-party installers, proxy the [whole installation shell](first-run.md#install-a-third-party-cli-through-the-proxy); prefer downloading and reviewing before execution rather than wrapping only the left side of a pipeline. Follow [upgrade instructions](update.md) for existing installations.
